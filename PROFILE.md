# Planomy Tax Data

A free, keyless open-data JSON API providing 2026 US retirement and tax figures — IRS contribution limits, income phase-outs, federal brackets, Social Security wage base and COLA, Medicare premiums and IRMAA, and RMD start age — sourced from IRS, SSA, and CMS. Served as a single static JSON file from the Planomy local-first personal-finance planner.

- **Provider:** https://planomy.net/data/
- **Documentation:** https://planomy.net/data/
- **Base URL:** https://planomy.net
- **Tags:** tax, finance, open-data, retirement, government
- **Public API:** yes
- **Agent-native (MCP / llms.txt / skills):** yes
- **Confidence:** 90/100

## APIs

- **Planomy Tax Data JSON** — A free, no-auth static JSON endpoint providing 2026 US tax and retirement data. Server-side consumable (not CORS-enabled). Includes a stable, additive field-level schema documented in prose. (`https://planomy.net`)

> The core interface is a single static JSON file at https://planomy.net/tax-data/2026.json (no key, no sign-up), not a multi-endpoint dynamic API. It is NOT CORS-enabled despite the submitted APIs.json claiming 'CORS-open' — it is intended for server-side consumption (curl/Node/Python/etc). A prose/field-level schema exists at https://planomy.net/data/#schema but there is no machine-readable OpenAPI/AsyncAPI/GraphQL/Postman contract. The apis.json at https://planomy.net/apis.json was referenced but could not be verified live. llms.txt is confirmed live. No MCP server (hosted or local) and no published agent skills were found. Data is public-domain, free to reuse.

## Correction — 2026-08-09 enrichment pass

Two claims above were tested and one is wrong:

- **CORS.** The note says the endpoint is "NOT CORS-enabled". As of 2026-08-09 both
  `https://planomy.net/tax-data/2026.json` and `https://planomy.net/tax-data/index.json` return
  `access-control-allow-origin: *`, so a simple cross-origin browser `fetch()` works. `OPTIONS`
  returns `405`, so preflighted requests still fail. Planomy's own documentation at
  `https://planomy.net/data/` also still says no CORS header is sent — the docs and the deployed edge
  disagree, and the original submission's "CORS-open" claim was closer to the truth than the
  correction applied to it. Because the header is undocumented it could be withdrawn without notice.
- **`https://planomy.net/apis.json`** was re-probed and returns **404**, confirming the note.

Also confirmed by probe on 2026-08-09: no OpenAPI (`/openapi.json`, `/openapi.yaml`, `/swagger.json`,
`/api-docs`, `/redoc` all 404 on the API host), no `/.well-known/` surface of any kind including
`security.txt` and both A2A agent-card paths, no MCP server, no packages on npm/PyPI/RubyGems/crates,
and no first-party GitHub organization. `llms.txt` and `llms-full.txt` are live.

Newly found and captured this pass: three free embeddable calculator widgets at
`https://planomy.net/embed/` with a loader at `https://planomy.net/js/embed.js`, and the Planomy
planner pricing (Free / Plus $6 mo / $60 yr) — neither of which gates the data API, which remains
free and keyless.
